- No advice framing as from an attorney or paralegal.
- No credit score guarantees in any UX copy.
- No integration with credit monitoring services' APIs (no third-party data ingestion beyond user-uploaded reports).
- No automated debt settlement negotiation (scaffolds only; user controls all sends).

## Architecture Decisions — Apex Additions (AD-6 through AD-15)

### AD-6 — Legal Intelligence Engine (LIE)

**Decision:** Create `src/services/legalIntelligenceEngine.ts` as a pure-TS, zero-AI, deterministic rule engine. It is the **source of legal truth** for all Strategy Cards. AI providers may *add prose* but cannot *override* LIE outputs.

**LIE outputs per item:**

```typescript
interface LegalProfile {
  itemId: string;

  // FCRA Section applicability
  fcra611Applicable: boolean;        // reinvestigation right
  fcra623Applicable: boolean;        // furnisher direct dispute right
  fcra609Applicable: boolean;        // disclosure / method of verification
  fcra605BApplicable: boolean;       // identity theft block (if fraud flagged)
  factaApplicable: boolean;          // free report / summary of rights

  // FDCPA (if collections)
  fdcpa809Applicable: boolean;       // debt validation right (CA/collector items)
  fdcpa807Applicable: boolean;       // false representation prohibition citation
  validationWindowOpen: boolean;     // within 30 days of first notice?

  // Metro2 compliance flags (from auditMetro2)
  metro2Violations: Metro2Violation[];

  // SOL intelligence
  solState: string;                  // governing state
  solYears: number;                  // from SOL matrix
  solExpired: boolean;
  solExpiresInDays: number | null;
  solDefenseApplicable: boolean;     // use SOL as dispute defense if collector
  reageingRisk: boolean;             // payment would restart SOL

  // DOFD / credit clock
  dofdConfidence: 'explicit' | 'inferred_from_delinquency' | 'missing';
  dofd: string | null;
  creditClockExpiresDate: string | null;   // 7-year mark
  creditClockExpired: boolean;
  obsoletionDisputable: boolean;           // past 7yr → remove regardless

  // Dispute angle legal anchors available
  availableAnchors: LegalAnchor[];

  // Restrictions
  disputeRestrictions: DisputeRestriction[];  // e.g., "Cannot claim DOFD unknown — field present"
  upriskFlags: UPLRiskFlag[];                 // UPL guardrails
}
```

**Acceptance:** LIE runs deterministically in <10ms per item; no AI call; fully unit-tested; all Strategy Cards must embed `legalProfile` reference.

### AD-7 — Debt-Type Strategy Library (DTSL)

**Decision:** `src/services/debtTypeStrategyLibrary.ts` — 12 debt-class strategy maps with unique dispute postures, angle sequences, evidence requirements, and bureau-response expectations.

**The 12 Debt Classes:**

| Class | Key Dispute Angles | Special Logic |
|-------|--------------------|---------------|
| **Revolving** (credit card) | Balance accuracy, credit limit reporting, payment history, charge-off date accuracy | Utilization impact simulation |
| **Installment** (auto/personal loan) | Payment history, payoff accuracy, account status post-payoff | Paid-in-full verification gate |
| **Mortgage** | Modification accuracy, foreclosure process violations, escrow reporting | High-stakes; evidence gate elevated to Tier 3 |
| **Student Loan** | Deferment/forbearance status, servicer transfer gaps, IBR/PSLF reporting | Federal vs private branch |
| **Medical** | HIPAA intersection, 1-year grace period (NCAP), medical debt reporting rules (2025 rules), balance accuracy | Auto-flag for new reporting rules |
| **Collections / CA** | Debt validation, original creditor identity, obsolescence, re-aging, duplicate with OC | FDCPA §809 validation branch |
| **Charge-off** | DOFD accuracy, charge-off date vs last delinquency, settlement reporting, sold-to-CA detection | Dual-account detection (OC + CA) |
| **Public Record** (pre-NCAP) | Already removed post-NCAP; flag as obsolete if still present | Tax liens/judgments |
| **Hard Inquiry** | Authorization (permissible purpose), obsolescence (2yr), duplicate pulls | Section 604 citation; separate dispute path |
| **Authorized User** | Remove if damaged (account holder dispute); establish if positive but missing | Identity match required |
| **Utility / Telecom** | Positive data reporting check; negative — late/collection dispute | Account-not-mine high frequency |
| **Mixed File** | Separate file indicators — wrong SSN suffix, unknown address, unknown account | Fraud/ID-theft escalation path |

### AD-8 — On-Device Classification Layer (Transformers.js)

**Decision:** Embed a lightweight quantized classification model via Transformers.js (WASM, no server) for:
- **Debt-type classification** from parsed account strings (supplementing parser field)
- **Frivolous-risk fast scoring** before any AI call (save API credits; speed up preflight)
- **Dispute angle plausibility** scoring for fast batch filtering
- **Bureau response sentiment classification** (photo/scan of response letter)

**Constraints:**
- Model size ≤25MB quantized (ONNX int8).
- Only runs on text already in IDB — no network.
- Outputs are **advisory signals** feeding Strategy Cards; LIE and hard rules override.
- Android: lazy-load on first Autopilot use, cache to private storage.
- Windows: bundled in Electron ASAR or lazy-fetch on first run, cache to userData.

**Files:** `src/services/onDeviceClassifier.ts`, `src/workers/classifierWorker.ts` (runs off main thread).

### AD-9 — Inquiry Dispute Module

**Decision:** Build `src/services/inquiryDisputeEngine.ts` + `src/pages/InquiryAudit.tsx` as a first-class dispute module for hard pulls.

**Workflow:**

```
Parse hard inquiries from credit report
        ↓
InquiryClassifier:
  - Date ≤ 2 years? (otherwise obsolete → auto-remove dispute)
  - Permissible purpose known? (mortgage/auto/employment/card/insurance)
  - Consumer-initiated? (correlate with known application history)
  - Duplicate pulls? (same creditor, same date ± 1 day = rate-shop exception vs true dup)
        ↓
Strategy per inquiry:
  - Obsolete (>2yr) → §605(a)(3) cite; factual removal demand
  - Unknown / Not-mine → §604 permissible purpose demand; ID theft gate
  - Duplicate (non-rate-shop) → duplicate cite; removal demand
  - Confirmed authorized → no dispute (block from batch)
        ↓
Letter generation (inquiry-specific DNA; separate from tradeline letters)
        ↓
Bureau-specific submission (inquiry disputes often go to special fax/address)
```

**Acceptance:** Inquiry disputes are never mixed with tradeline disputes in a single letter. Each bureau's inquiry dispute contact info is stored in `bureauContactMatrix.ts`.

### AD-11 — Score Impact Simulator

**Decision:** `src/services/scoreImpactSimulator.ts` — local heuristic model (no cloud, no FICO license) that estimates credit score delta from hypothetical changes. **Clearly labeled as estimate, not FICO/VantageScore calculation.**

**Simulation factors (VantageScore 3.0 / FICO 8 weight approximations):**

```typescript
interface ScoreSimulation {
  hypotheticalRemovals: string[];  // itemIds
  hypotheticalCorrections: ScoreCorrection[];

  estimatedDelta: {
    low: number;      // conservative estimate
    mid: number;      // central estimate
    high: number;     // optimistic estimate
  };

  drivingFactors: ScoringFactor[];
  // e.g., { factor: 'derogatory_removal', impact: '+25–45', confidence: 'medium' }

  utilizationChange?: number;      // if balance correction changes util
  ageMixChange?: string;           // if account removal affects mix/age
  collectionClearance?: boolean;   // collections have outsized impact

  disclaimer: string;  // always shown; non-FICO estimate language
}
```

**UI:** Score Simulator screen with slider "If these items were removed/corrected, estimated score change: +XX to +XX." Shown before cycle, after cycle, and in dispute review.

**Acceptance:** Simulator never shows a single number — always a range. Disclaimer is non-dismissible first time.

### AD-13 — A/B Letter Strategy Tracker (Local Experiment Engine)

**Decision:** `src/services/abStrategyTracker.ts` — tracks which dispute angle variants produce deletions/corrections vs verifications/no-response, bucketed by bureau + creditor class + debt type.

## Apex Letter Generation — World-Class Letter Intelligence

### Letter Intelligence Upgrades (extending LetterGeneratorV2 + DNA12)

**L1. Legal Citation Depth**

Every letter must include citations drawn from `legalProfile`. Citation rotation (existing) extended with:
- FDCPA citations for collections (§807, §809, §813)
- Metro2 specific violation codes (e.g., Compliance Condition Code violation)
- FACTA citations where applicable
- State-level FCRA analogs (California CCRAA, New York FCRA, etc.) — opt-in per user's state

**L2. Debt-Type Voice Templates**

12 debt-class voice profiles in `debtTypeVoicePolicy.ts` — different linguistic register, evidence emphasis, and bureau-address logic per class. Collections letters emphasize validation rights. Medical letters emphasize grace period and new rules. Mortgage letters are elevated in formality.

**L3. Furnisher-Direct Dispute Branch**

## Apex Merge Architecture — Extended

Building on V5.0 AD-1/AD-2 plus:

### M1. Account Identity Graph (AIG)

**New concept:** Instead of pairwise comparison only, build an in-memory **Account Identity Graph** across all parsed items.

```typescript
interface AccountIdentityGraph {
  nodes: AccountNode[];   // one per distinct parsed account
  edges: MergeEdge[];     // scored relationships between nodes

  // Graph outputs
  mergeGroups: MergeGroup[];     // connected components → AUTO_MERGE candidates
  linkGroups: LinkGroup[];       // campaign groups → LINK_ONLY candidates
  isolated: AccountNode[];       // no meaningful relationships
  conflicted: ConflictPair[];    // hard refuses with reasons
}
```

**Why graph vs pairwise:** Prevents transitive merge errors (A→B ok, B→C ok, but A→C would be wrong — graph detects triadic closure violations before merging).

### M2. Creditor Alias Matrix

**New:** `src/data/creditorAliasMatrix.ts` — curated list of known creditor name variants, sold-portfolio chains, and alias families.


Existing balance comparison upgraded:

```typescript
function balanceCompatible(a: ParsedAccount, b: ParsedAccount): BalanceCompatibility {
```

### M4. Duplicate OC + CA Detection

**Critical new logic:** Many consumers have both the original creditor (charged off) AND a collection agency for the same debt — both should appear but as LINK_ONLY (same debt, not same account). Current system may wrongly merge or wrongly separate.

```typescript
function detectOCCARelationship(a: ParsedAccount, b: ParsedAccount): OCCARelationship {
  // Signs: A is charge-off status, B is collection/CA account type
  // Same approximate balance or B slightly higher
  // A DOFD is earlier; B open date is later than A charge-off date
  // Creditor name: A is bank/retailer; B is known CA from alias matrix
  // Decision: LINK_ONLY with campaignGroupId — dispute CA first
}
```

## Apex Outcome Learning — Closed-Loop Intelligence

### Outcome Classification Upgrade

**More granular outcome taxonomy:**

```typescript
type DisputeOutcome =
  | 'deleted'                    // account removed from bureau
  | 'corrected_status'           // status changed (e.g., late → paid)
  | 'corrected_balance'          // balance updated
  | 'corrected_dofd'             // DOFD corrected
  | 'corrected_payment_history'  // late payments removed/corrected
  | 'corrected_account_type'     // account type fixed
  | 'verified_no_change'         // bureau says it's correct
  | 'verified_with_investigation'// reinvestigated and reaffirmed
  | 'no_response'                // 30/45 day window elapsed, no response
  | 'frivolous_rejection'        // bureau called it frivolous
  | 'request_more_info'          // bureau requested documentation
  | 'transferred_to_furnisher'   // bureau redirected to furnisher
  | 'obsolete_removed'           // automatic removal (7-year clock)
  | 'goodwill_accepted'          // goodwill deletion granted
  | 'debt_validated'             // CA validated the debt
  | 'debt_not_validated'         // CA failed to validate → remove
  | 'inquiry_removed'            // inquiry deleted
  | 'statement_added';           // consumer statement attached

```

**Outcome → Strategy adaptation:**

| Outcome | Strategy Card Next Cycle |
|---------|--------------------------|
| `deleted` | Clear item; record win in A/B tracker; boost same angle/bureau confidence |
| `corrected_*` | Partial win; verify correction on next report; if corrected field was disputed field → close |
| `verified_no_change` | Rotate angle; increase pass; if pass 3+ → consider furnisher direct |
| `verified_with_investigation` | Strong furnisher claim → pivot to §623 furnisher direct |
| `no_response` | Inertia escalation (existing); add "failure to respond" cite in next letter |
| `frivolous_rejection` | Hard hold; require new angle + new evidence; reset frivolous counter |
| `request_more_info` | Evidence gate opens; guided document attach; re-letter with docs |
| `transferred_to_furnisher` | Branch to furnisher-direct workflow |
| `debt_not_validated` | Prepare demand letter for removal with FDCPA cite |
| `goodwill_accepted` | Clear; record in A/B tracker as goodwill win for creditor class |

## Non-Negotiable Principles — Apex Additions

All V5.0 principles preserved. Apex adds:

16. **Legal intelligence is deterministic, not AI-generated.** LIE runs before any AI call. AI cannot override SOL, DOFD, or FCRA applicability decisions.
17. **Anti-fabrication is a hard gate, not a warning.** No letter with invented data passes preflight. Ever.
18. **UPL risk is actively blocked.** Phrase blocklist, persona check, and voice scoring together. Not just a policy.
19. **The consumer is always the author.** Letters use first person consumer voice. AI assists; consumer sends.
20. **Education is contextual, not a tutorial wall.** One lesson, at the right moment, once.
21. **Score simulation is always a range with a disclaimer.** Single-point score claims are prohibited in all UX copy.
22. **Goodwill letters are never FCRA disputes.** No legal citations. No demand language. Clearly separated in UI and letter DNA.
23. **Campaign types don't mix in a single letter.** Tradeline disputes, inquiry disputes, goodwill, and debt validation are always separate documents.
24. **The audit record is always exportable.** No dispute action is ever un-auditable.
25. **Performance is a feature.** Slow cycle planning degrades trust. Budget enforced in CI.
